# Бюро

Учебный сервис бронирования переговорок на Spring Boot.

## Стек

- Java 17, Spring Boot 4.1.2
- Spring Web, Spring Data JPA, Bean Validation
- H2, JUnit 5, Mockito

## Запуск
`./mvnw spring-boot:run`


Сервис поднимается на `http://localhost:8080`.

Для пробного запуска с тремя переговорными:

```sh
./mvnw spring-boot:run -Dspring-boot.run.profiles=demo
```

Для доступа с телефона подключи оба устройства к одной Wi-Fi сети. Запусти один экземпляр приложения для обоих устройств:

```sh
./mvnw spring-boot:run -Dspring-boot.run.profiles=demo -Dspring-boot.run.arguments=--server.address=0.0.0.0
```

На компьютере доступен также адрес `http://localhost:8080/`. Для проверки на обоих устройствах открой `http://192.168.1.64:8080/`, подставив адрес своего компьютера. Это локальное HTTP-демо, используй для него отдельный тестовый пароль. В профиле demo аккаунты и встречи сохраняются в локальной папке `data/`.

Зарегистрируйся по почте, укажи имя и отдел. На главной странице выбери дату и время, проверь доступность и нажми на
переговорную на плане. После бронирования её статус обновится.
В демонстрационном плане комнаты сопоставляются по уникальным названиям,
а запрос на бронирование использует ID, полученный от сервера.

## Эндпоинты

| Метод | Путь | Описание | Ответ |
|---|---|---|---|
| GET | /hello?name=... | Проверка DI | 200, текст |
| GET | /rooms | Список комнат | 200, JSON-массив |
| GET | /rooms/availability | Доступность комнат на выбранный интервал | 200, JSON-массив |
| POST | /rooms | Создать комнату | 200, JSON с id |
| POST | /bookings | Создать бронь | 200, JSON с id |

Тело `POST /rooms`: `{"name":"Переговорка 1"}`.
Тело `POST /bookings` (с активной сессией сотрудника): `{"roomId":1,"purpose":"Планирование","startTime":"2026-11-03T10:00:00","endTime":"2026-11-03T11:00:00"}`.

Пример проверки доступности:

```sh
curl 'http://localhost:8080/rooms/availability?startTime=2026-11-03T10:00:00&endTime=2026-11-03T11:00:00'
```

Ответ содержит `roomId`, `name` и `available` для каждой комнаты.
Обе даты передаются в локальном времени. Если одна бронь заканчивается ровно в начале
запрошенного интервала, она не мешает забронировать комнату. При создании брони
сервер снова проверяет, свободна ли комната.

## Ошибки

| Код | Когда |
|---|---|
| 400 | Пустое или отсутствующее поле, конец брони раньше начала |
| 404 | Комната с таким id не найдена |
| 409 | Комната уже занята в это время |

## Тесты

`./mvnw test`


Unit-тесты сервиса (Mockito) и интеграционные тесты HTTP-слоя (MockMvc).

## Ограничения

- При запуске без профиля demo используется база в памяти.
- Проверка пересечений не защищает от одновременных запросов (гонка между проверкой и записью).
- Бронь возвращается с кодом 200, а не 201 Created.
- Ответ содержит сущность `Booking` напрямую, DTO для ответа не сделан.

Ограничения записаны намеренно: их полезно уметь назвать на собеседовании.
